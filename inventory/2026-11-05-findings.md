## Findings

### F1 — Ghostty config is broken (LOW visible impact, easy fix)
`~/.config/ghostty/config` line 1 is `9oˆ˚≥≤0p.font-family = "JetBrainsMono Nerd Font"`.
`ghostty +validate-config` → `unknown field`. **The font setting is ignored.**
The stray chars `ˆ˚≥≤` are exactly what macOS produces for Option+`i k . ,` — likely an Option
(home-row-mod) misfire while typing vim keys. Also: an empty second config file exists at
`~/Library/Application Support/com.mitchellh.ghostty/config.ghostty` (two locations = confusion).
Fix: remove the prefix; keep a single config location (the one kebo will symlink).
Impact (re-checked 2026-11-06): Ghostty's built-in default font is already JetBrains Mono with
Nerd Font symbols, so the fallback looks almost identical — that is why it went unnoticed.
Timeline: `config.ghostty` (empty template) modified 2026-10-12 21:12; `config` created
2026-10-12 21:16 and last modified 2026-11-03 16:29 — Ghostty does not write this file, so it was
hand-edited. `9o` and `0p` are vim normal-mode commands, consistent with typing them in insert mode.
Verify: `ghostty +validate-config` (exit 1), `ghostty +show-config | grep font-family` (empty), `cat -v`.

### F2 — Herdr prefix `Ctrl+a` shadows "line start" everywhere (HIGH, decision)
Herdr intercepts `Ctrl+a` before any program in a pane. Lost inside Herdr:
- zsh (emacs readline): beginning-of-line
- Pi / Gentle Shell: `tui.editor.cursorLineStart` (`ctrl+a`); `/tree` filter "all"
- Claude Code: line start
- Neovim: increment number (`<C-a>`)
Herdr 0.9.1 documents **no send-prefix action** (no "press twice to send literal"). Verify manually:
inside Herdr, in zsh, type text and press `Ctrl+a Ctrl+a`.
Every alternative prefix also has an owner: `Ctrl+b` (cursor left, Herdr default), `Ctrl+Space`
(LazyVim treesitter selection). Options → ADR 0006.

### F3 — Option is not Alt in Ghostty (MEDIUM, decision)
`macos-option-as-alt` is unset, so `Option+b/f/d/y` insert `∫ ƒ ∂ ¥` instead of readline word ops
(zsh, Pi `alt+b/f/d/y`, Herdr text fields). Ghostty only patches `alt+arrow` by default.
Caveat: setting it to `true` breaks typing accents/ñ with Option if you use the US layout.
Likely answer: `macos-option-as-alt = left` (left Option = Alt, right Option = accents).

### F4 — Ghostty already respects the contract (GOOD)
